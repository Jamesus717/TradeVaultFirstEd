## Gotchas
- **Supabase MCP holds any SQL containing `DROP` for a confirmation that never shows, so it times out.** Use `ALTER POLICY` / `CREATE OR REPLACE TRIGGER` instead. `apply_migration` also timed out. `execute_sql` worked.
- Policies on `trade_listings` must not query `conversations` directly (infinite recursion with the conversation insert policy). Use `tb_is_conversation_participant()`.
- Don't add client-side inserts into `notifications` or system `messages`. They're refused now.
- The Pokémon API is flaky (random 500/502). `pokemonFetch` retries up to 4 times.
- Supabase flags `tb_is_conversation_participant` as callable by signed-in users. That's intended: it only says if *you* are in a conversation about a listing.
